## 模型输出全文

### 0. 前置判断：先合规，再资助，最后才谈平台

从政策与评审视角，这个项目当前最大的风险不是技术，而是**「以文化保育之名收集长者个人资料，但资料治理能力尚未建立」**。审计已发现三处硬伤：consent 文案承诺「暂不永久储存」、实际却写入前端 `localStorage`；四级隐私只有界面、无服务端过滤（「我的」页更正/撤回为「準備中」）；录音无后端记录 CRUD、无删除日志。

任何一份资助申请或政府/社区合作提案，只要被问到「参与者如何撤回同意、资料保留多久、谁有权查阅」，当前系统都答不上来。因此顺序必须是：**W1–2 补齐资料治理最小闭环 → W3–4 通过信任中介完成真实采集 → W5–6 才提交资助/合作意向**。倒过来做，等于把合规风险写进申请书。

以下所有资助名称、 eligibility、金额与条款均须以官方最新指南核实【待验证】；我不提供未经核实的金额或成功率。凡引述团队文档的内容，标注为「团队文档自述」，不作为一手来源。

### 1. 资助路径匹配

| 路径 | 政策偏好（须核实） | 与本项目的匹配点 | 成功申报要点 | 风险 / 前置条件 |
|---|---|---|---|---|
| **CCFS 乡郊保育资助计划** | 乡郊保育、村落活化、社区参与及可延续的保育成果【待验证：最新申请指南与资助范围】 | 主题最贴合：新界乡村口述史、村落记忆保存 | 需有**乡郊社区伙伴/村代表支持**与可交付的非虚构成果（档案、教材、展览）；预算要有社区参与与后期维护，不能只买 API | 团队目前零真实社区伙伴、零真实长者录音；无伙伴几乎不可能通过。须先拿到 1 个 NGO/村组织合作意向 |
| **ITF 创新及科技基金** | 本地研发、技术创新性、可产业化【待验证：具体计划与申请资格】 | 只有当我们把「可验证 grounding + 方言评测集 + 离线双引擎」定义为研发课题时才匹配 | 需明确技术不确定性、研发里程碑、自有 IP 归属、本地研发主体 | 当前是 API 拼接 + 客户端关键词匹配，研发成分不足；先产出《技术不确定性说明 + 评测协议》 |
| **SIE Fund 社会创新及创业发展基金** | 社会成效、可量度的受益群体、可持续营运【待验证：须经其委聘的中介机构申请】 | 长者参与、代际共融、文化平权等社会成效指标 | 需有清晰的社会成效量度框架（如参与者数、回访率、长者主观反馈）与合作伙伴 | 需要可验证的受益数据，role-play 不算 |
| **赛马会慈善信托 / 其他慈善资助** | 项目制、可量度社会影响、机构资质【待验证：个别计划主题与申请窗口】 | 代际共融、社区文化保存 | 需注册机构/合作机构作为申请主体、完整评估设计与审计报告 | 学生团队一般需挂靠 NGO/院校；先确认申请主体资格 |
| **HKSTP Ideation / 比赛衔接资源** | 早期创科团队孵化【团队文档自述：获奖直通 Ideation、最高 HK$100,000 种子资助，须核实】 | 与 Techathon+ 赛道直接衔接 | 展示技术可演示性与商业假设的验证计划 | 属 runway，不是收入；且需通过比赛结果触发 |

**共同成功要素（四类资助都看）**：① 一个具资质的合作/申请主体；② 真实社区伙伴与书面支持；③ 可量度的交付与成效；④ 资料治理与伦理审查文件；⑤ 完成后档案的**移交与长期保存方案**（文档 roadmap 已写 handover to library/museum，可对接「香港记忆 HK Memory」这类静态档案机构，做它的「活体前端」而非竞争方）。

**建议的申报组合**：短期以「CCFS / 院校或 NGO 合作的小额项目制资助 + 比赛孵化资源」为主，把 ITF 作为技术路线成熟后的第二阶段；不要在同一份申请里同时讲「公益保育」和「商业 SaaS」，评审会认为定位不清。

### 2. 基层治理破冰：把「信任」制度化，而不是靠一次拜访

新界乡郊的信任结构是**人际关系 + 机构背书 + 可追责的中介**，不是 App 下载量。设计三层信任中介：

**第一层 · 机构背书（进村之前）**
- 目标：拿到 1 个可被长者识别的本地机构背书。候选已在团队文档中列出：关爱队（District Care Teams）、区长者中心、乡事委员会/村代表、信义会 / 明爱 / 长春社等 NGO【待验证：各区实际对口单位与联络窗口】。
- 产出：一份一页纸《采录说明》（用途、谁在收集、资料去向、可随时退出、不涉征地与产权评价），由机构盖章/署名；一份合作意向书。
- 纪律：**不以「比赛/获奖」为进村理由**，以「为村落留一份可回放的声音档案，副本交回村内保管」为理由。

**第二层 · 双人协同采录（现场）**
- 采用团队已确认的方向：青年志愿者/社工持机引导，长者只自然讲话，不注册、不看地图、不做隐私层级选择（隐私范围由长者口头确认、由操作者代录并复核）。
- 用**问题卡片**取代开放式提问（呼应文档末尾方案 3）：一张卡一个问题，围绕不涉及产权与纠纷的生活记忆（儿时村落、节庆、农事、声音），预设 8–12 张卡；长者可选卡、可跳过、可随时终止。
- 现场三件套：纸质同意书（大字繁体）+ 口头说明录音（作为同意过程证据）+ 现场回放确认（长者听一遍，指出要删的段落）。
- 村代表/长者中心职员作为见证人签字，形成「机构—志愿者—长者」三角可追责关系。

**第三层 · 事后复核与撤回（离开之后）**
- 7 日内由机构转交一份副本给长者/家属，附「更正与撤回」联络方式（电话优先，不要求长者用 App）。
- 撤回请求走人工工单，技术上必须能真正删除音频、转写、衍生文本与缓存；**当前系统没有删除日志、没有后端记录，这一层尚未实现，是落地前必补项**（Zheng）。
- 建立志愿者名册与培训/保密承诺，避免同一志愿者跨村处理敏感内容。

**治理节奏建议**：1 个区 → 1 家长者中心 → 1 位村代表 → 首场 6–8 位长者小组工作坊 → 复盘后再扩。先把 SOP 跑通一次，比同时铺五个村更能形成可写进资助申请的「制度化证据」。

### 3. PDPO 合规：数字采录知情同意与脱敏 SOP

> 说明：以下按香港《个人资料（私隐）条例》（PDPO）的通用原则框架（收集目的与最小必要、准确性、保留期限、保安、查阅与更正、使用限制）与 PCPD 常见实务指引组织；**具体条文编号、跨境传输要求与最新指引须由 Dat 核对 PCPD 官方文本【待验证】**，本报告不引述未经核实的条文号。

**3.1 资料盘点（先做，1 天）**
逐项列出：原始音频、逐字稿 raw_text、词级 words[]（含置信度）、formal_text、qa_list、Q&A 引用片段、模糊地理（村级 800m 圈）、讲述者姓名/称谓、同意书扫描、聊天记录（前端 localStorage）、服务器与第三方日志。每项标注：是否个人资料、敏感程度、收集目的、保留期、存放位置、可删除性。

**3.2 分级同意（collection）**
- 同意必须**分项、可撤回、书面 + 口头说明双留痕**，且用长者能理解的大字繁体中文/粤语说明。
- 分项至少包含：① 是否录音；② 使用范围（私人 / 家人 / 社区 / 公开，四级）；③ 是否允许用于比赛演示与公开网页；④ 是否允许用于 future AI 训练/评测（默认**否**，需另行单独同意）；⑤ 保留期限；⑥ 撤回方式。
- **禁止捆绑**：不得把「参与采录」与「同意公开」绑成一个勾选框。
- 儿童/认知能力受限长者的同意与见证安排须另定【待验证：实务指引】。

**3.3 敏感言论脱敏（use & accuracy）**
- 采集阶段：问题卡片主动避开征地补偿、历史产权、家族纠纷、在世第三人评价；长者主动提及时，操作者不追问、不引导。
- 处理阶段：建立「敏感片段」标记（人名、门牌、地界、金额、纠纷指控），默认不进入公开索引；脱敏采用**片段级裁剪 + 代称**，而非让 LLM 改写原句——改写会破坏「原音与逐字稿一致」的诚实性红线，正确做法是「不公开该片段」并保留内部审计副本。
- 展示阶段：地图只用村级 800m 模糊圈、不放 GPS 标记；Q&A 答案只由已授权片段拼接并附出处，未授权内容不得进入检索池（**检索前过滤，不是检索后遮挡**）。
- 团队红线「不做语音克隆/TTS」在此有额外合规价值：避免产生可冒充在世/已故长者的合成语音，降低身份滥用与再度同意争议。

**3.4 保留、撤回与删除（retention & erasure）**
- 为每类资料设保留期；到期自动复核而非无限期保存。
- 撤回工单 → 删除音频、转写、formal_text、qa_list、检索索引、缓存与备份中的对应条目 → 生成**删除日志**（时间、操作人、范围、第三方通知）→ 回执给长者/机构。
- 技术前提：需要服务端记录 CRUD 与可定位的 record id；当前 `/api/process` 不落盘、无 id，前端 localStorage 无审计日志，**撤回权目前无法工程化兑现**。这是最先要修的合规债。
- 同时修正 consent 文案与实际存储不一致的问题（审计 `zheng-nov-03-audit.md:25`），否则构成误导性收集。

**3.5 第三方与跨境（security & transfer）**
- 音频送 Google Cloud STT、文本送 Gemini 属于向第三方披露，须在收集声明中写明服务商、目的、处理性质与可能的数据区域；核实服务条款是否允许训练用途、能否指定区域【待验证】。
- 若数据可能离开香港，须按 PCPD 相关指引评估并落实适当保障措施【待验证：具体条文与最新指引】。
- 访问控制按角色分离（访客 / 志愿者 / 管理员），密钥不入库不入前端（README 已声明 zero API keys committed）；同意书扫描件与音频分库存放。

**3.6 最小可行合规包（给 Dat / Zheng 的交付清单）**
1. 一页纸《收集个人资料声明》（PICS 形式）与分项同意书模板；
2. 资料盘点表 + 保留期矩阵；
3. 敏感片段标记与脱敏规则（含「不公开而非改写」原则）；
4. 撤回/更正工单 SOP + 删除日志实现；
5. 志愿者保密承诺与培训包；
6. 第三方处理清单（Google STT / Gemini / 托管服务）与数据区域说明。

### 4. 三阶段落地建议

| 阶段 | 时间 | 目标 | 可写进申请书的证据 |
|---|---|---|---|
| 一 · 合规补债 | W1–2 | consent 与实际一致、服务端隐私过滤一条路径、删除日志 | 合规包 1–6 + 代码提交记录 |
| 二 · 真实采集 | W3–4 | 1 个区、1 家机构、首场工作坊、≥1 段真实录音 | 合作意向书、签署同意书、现场回放确认记录 |
| 三 · 资源对接 | W5–6 | 依证据选择 CCFS / SIE / 院校合作路径 | 成效量度框架 + 档案移交方案 + 预算表 |

**最后一句提醒**：政策与资助评审看的是「谁授权你收集、你如何保护、完成后交给谁」。把这三问答成可出示的文件，比再叠一个 AI 功能更能提升项目可信度。
