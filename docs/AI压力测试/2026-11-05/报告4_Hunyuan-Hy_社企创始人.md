- **技术栈**：FastAPI 后端（server.py），POST /transcribe 核心管道 = Google Cloud STT (language_code="yue-Hant-HK", 词级时间戳+词级置信度) → Gemini 防幻觉结构化提取（formal_text + qa_list，严禁编造）→ 统一 JSON 返回；前端为单页应用（Leaflet + OSM 地图、800 米模糊半径隐私圈、录音抽屉、知情同意弹窗、音文字幕跳轨、村口问答 FAB），390px 移动端优先，Oat × Sage 配色，WCAG 触控标准。
- **团队（5 人）**：Douglas（商业战略/评委反馈/NGO 联络/路演 Deck）、Zheng（后端与部署）、Steven（前端 UI/UX）、Boris（粤语音频测试集与黄金标准校对）、Dat（优先级统筹/用户访谈/知情同意与隐私合规审查）。
- **已知短板（自认）**：零真实用户/社区伙伴（全部故事为 role-play）；隐私层级只有界面无后端；粤语 ASR 依赖 Google Cloud STT 非自研；商业模式模糊；除粤语外三种方言无 ASR 模型；团队全为 ITM 背景。
- **团队红线（方案不得违反，若突破必须论证例外价值）**：不做语音克隆/TTS「复活」逝者；不做社交 feed/点赞/关注；consent-first（知情同意优先）；隐私优先（四级隐私：私人/家人/社区/公开，服务器端过滤）；诚实标注（角色扮演示范故事必须标明，demo-scope 不外推为生产性能）。

## 模型输出全文

### 0. 冷启动的真正瓶颈不是流量，是「信任」和「可出示的证据」

团队当前唯一故事是角色扮演、零真实长者、零社区伙伴。这个阶段做增长黑客会适得其反：把 demo 当真实故事传播，等于自毁「诚实标注」红线，也是评委最容易抓的把柄。

所以冷启动目标要精确定义：**不是拉新用户，而是拿到 1 个可复用的「真实采集闭环」**——1 家社区机构背书 → 1 场工作坊 → 1 段真实录音 + 真实同意书 → 长者事后确认与可撤回 → 一段可对外展示、且明确标注来源的真实声音。把它跑通一次，后面每一场都是复制粘贴。

文档末尾指派给 Zheng 的 4 条方案里，方案 1（强化互动感）和方案 3（问题卡片/社交卡/故事卡）正好是这个闭环的产品载体；方案 2（地图动态感）是把它放大成公共叙事的舞台。下面把三者串成一套可执行的运营方案。

### 1. 采录 SOP 重构：让长者「不碰手机」，让年轻人「有话可问」

**核心改动**：把产品从「长者独立使用 App」改成「志愿者持机 + 长者讲述」的双人协同工作坊。团队自己的评委反馈矩阵已经承认「把手机塞给 80 岁长者不是合格的产品设计」，这条必须落到 SOP，而不只是写在应对话术里。

**问题卡片（方案 3 的落地形态）**
- 设计 8–12 张实体卡片 + 同版 App 内卡片，一卡一问，大字繁体，配旧照片/物件图作破冰道具。
- 题目只问生活记忆，不问产权与纠纷：「你细个喺边度玩？」「村口以前有咩声音？」「过年最记得边一味餸？」「以前点样去墟市？」——避开征地补偿、地界、在世第三人评价（见报告 2 的脱敏规则）。
- 卡片分三层递进：暖身（物件/照片）→ 生活（节庆/农事/声音）→ 地方（村落变化）。长者可以抽卡、跳过、随时停。
- 卡片背面印「这段会被谁听到」的四档范围图示，把抽象的四级隐私变成可指着的纸面选择，由志愿者代录并二次口头确认。

**45 分钟工作坊脚本（1 名主持 + 1 名操作志愿者 + 4–6 位长者）**

| 时段 | 动作 | 产出/纪律 |
|---|---|---|
| 0–5 min | 机构职员开场背书，说明「为村落留一份声音副本，副本交回村内」 | 不以「比赛/获奖」为理由 |
| 5–10 min | 纸质大字同意书 + 口头说明（口头说明本身录音留痕）；确认使用范围与保留期 | 分项同意，可随时退出 |
| 10–30 min | 抽问题卡片对谈，志愿者持机录音，不纠正、不引导、不追问敏感话题 | 每段 1–3 分钟，而非假设长者一次讲 51 秒以上 |
| 30–38 min | 现场回放：长者听一段，指出要删的段落、要改的字 | 现场修正记录，是最便宜的人工兜底 |
| 38–45 min | 交回执卡（含电话撤回渠道），约定 7 日内回访送副本 | 撤回不依赖 App |

**为什么顺手解决技术问题**：短卡片答案天然把音频切成小段，直接产出报告 3 所需的 `segment`；现场回放确认就是「第 2 层人工兜底」的线下版本，能显著降低 LLM 自动打标的错误率与后期人工质检成本（报告 1 的 `C_unit`）。**运营 SOP 与数据架构在这里是同一件事**。

**站内「强化互动感」的边界（方案 1）**：可以做「访问者给村落留一个问题」的结构化问题队列（文档 P0 问答广场），由长者/志愿者用声音回答后再走完整审核与溯源管线；**不做**信息流、点赞、关注、评论。理由沿用文档的辩证：把「社交」收敛为「代际对话」，只有「问题」一种交互，既提升参与感又不碰 no-social-feed 红线。这一条要写进产品说明，避免评审误判。

### 2. 高校 Service-Learning 矩阵：把志愿者供给做成课程，而不是招募海报

一次性招募的学生志愿者流失率极高；可持续供给来自**有学分、有导师、有固定学期节奏**的课程合作。

**三层合作对象**

| 层级 | 对象 | 给对方的价值 | 我们得到 |
|---|---|---|---|
| 课程层 | 通识 / Service-Learning / 数码人文 / 社会工作 / 语言学课程教师 | 现成的田野方法教材、真实社区议题、可评分的反思作业 | 每学期稳定的志愿者班底与学术背书 |
| 机构层 | 高校 Service-Learning 中心、书院、学生事务处 | 可复制的服务项目与风险评估模板 | 场地、保险、行政与伦理审查支持【待验证：各校流程】 |
| 社区层 | 长者中心、关爱队、NGO（团队文档列出信义会、明爱、长春社等） | 代际活动、可留存的村落档案副本 | 进村合法性与长者招募 |

**最小可行合作包（给老师的一页纸 + 一个文件夹）**
1. 课程模块大纲（3 周：伦理与同意 → 问题卡片与访谈 → 转写校对与档案移交）；
2. 志愿者培训包（30 分钟视频 + 一页红线卡：不诱导、不改写原音、不公开未授权片段、不追问产权纠纷）；
3. 现场工具包（卡片、同意书模板、录音检查清单、撤回工单流程）；
4. 评分建议（反思报告 + 校对质量 + 社区回赠物），便于教师直接嵌入现有评分框架；
5. 保险/风险与资料处理说明（与报告 2 的 PDPO 合规包共用）。

**供给漏斗（只给公式，不编数字）**
```
学期可采集段数 = 合作课程数 × 每班人数 × 每人负责长者数 × 到场率 × 有效同意率 × 质检通过率
```
每个乘数由第一场工作坊实测填入。**先做 1 门课 × 1 个班的首场**，拿到真实乘数再谈规模，否则矩阵只是 PPT。

**留存机制**：志愿者署名进入档案元数据 `reviewer_id`（报告 3 的 schema 已预留）、服务时数证明、优秀校对者成为下一期「组长」、期末办一场村落声音回放会让学生看到自己的成果被长者认领。认可感比补贴更能留住人，成本也更低。

### 3. 传播与认同营造：站外做情绪，站内守红线

**内容母题**：不是「AI 转写多准」，而是「一段即将消失的声音」。三条高共鸣线索——① 村落的声音（叫卖、祠堂、火车、蛙声）；② 物件与一句话（一张旧照 + 15 秒原音）；③ 代际对照（孙辈问、祖辈答）。

**站外玩法（Instagram / 小红书）**
- **声音明信片**：一张村落旧照/手绘 + 15–30 秒已授权原音 + 二维码，扫码听完整段并看到处（沿用产品已有的时间戳出处逻辑）。图文平台无法直接播音，二维码是必要的桥。
- **声音地图打卡**：以「北区声音地图」为话题，系列化发布不同村落；地图只用村级模糊圈，不放精确位置（隐私红线）。
- **代际提问接力**：把问题卡片拍成短视频模板，邀请网友问家中长辈同一个问题，形成 UGC 但不回流到站内 feed。
- **动态地图作为公共叙事（方案 2）**：用公开发展范围/清拆时间表叠加「记忆抢救紧迫度」，做一张「为什么是现在」的可视化长图；**数据须先核实公开来源与使用条款【待验证】**，未核实前只做示意 mock 并标注「示意，非官方数据」。

**纪律（比创意重要）**
- 每条对外内容标注：真实采集 / 角色扮演示範故事，二选一，不得混用；性能与识别率表述一律限定 demo-scope。
- 只使用已签署同意且范围包含「公开」的片段；涉人名、门牌、纠纷的片段不公开（不改写、直接不公开）。
- 站内不增加 feed/点赞/关注；所有「互动感」落在问题卡片与问题队列上。
- 不把长者包装成「被拯救者」，表述为「讲述者 / 共同作者」，档案副本回赠村内——这决定社区愿不愿意有第二场。

### 4. 6 周冷启动计划与指标

| 周 | 动作 | 关键指标（真实值，不用 demo 充数） |
|---|---|---|
| W1 | 定 1 个区、1 家长者中心/NGO；出同意书、卡片、培训包 v0.1 | 书面合作意向 ≥1 |
| W2 | 与 1 位课程教师确认合作；志愿者 6–8 人培训 + 保密承诺 | 培训完成人数、红线测验通过率 |
| W3 | 首场工作坊（4–6 位长者） | 真实录音段数、有效同意书份数、现场修正条数 |
| W4 | 7 日内回访送副本 + 撤回渠道验证；转写校对与人工兜底 | 回访完成率、撤回/更正工单数、质检通过率 |
| W5 | 首条「声音明信片」发布（真实片段、已授权） | 扫码听原音次数、二次转发；不看点赞数作为项目指标 |
| W6 | 复盘成 SOP v1.0 + 服务学习合作包 + 一段可进 pitch 的真实 30 秒声音 | 可复用 SOP、可出示的证据链、下学期合作课程数 |

**最终交付给评委的一句话**：我们不再用自己演的故事证明产品，而是拿一段有同意书、有出处、长者本人听过并确认过的真实声音开场——然后才讲 AI。

## 模型间差异备注（对比其他模型时填写）

- 与 DeepSeek 版报告的差异：尚无该模型版本，待复测。
- 与 GPT / Claude / Gemini 版报告的差异：尚无该模型版本，待复测。
- 更优的点：把运营 SOP 与 `segment` 切分、人工兜底、单条成本直接连起来，避免「运营方案与技术架构两张皮」；明确站内互动的红线边界，未把 no-social-feed 当可随意突破的约束；所有规模指标只给公式与实测要求。
- 更差的点：未核实各高校 Service-Learning 学分认定流程、保险与伦理审查要求，也未核实社媒平台对二维码/音频外链的实际规则，均需团队按【待验证】补齐；单模型单轮输出，缺少跨模型对抗复核。
